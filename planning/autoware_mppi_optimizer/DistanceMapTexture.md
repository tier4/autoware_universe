# Texture-Accelerated ESDF Costmaps for MPPI

## Overview

This document outlines the optimization architecture for the Model Predictive Path Integral (MPPI) controller's barrier-cost functions.

Traditionally, MPPI rollout kernels calculate Euclidean distances to obstacles, road borders, and drivable areas analytically for every sampled trajectory at every timestep. In dense environments, this creates an $O(N)$ computational bottleneck and severe GPU warp divergence.

To resolve this, we decouple the geometric distance calculations from the MPPI rollout kernel. Instead, we precompute Euclidean Signed Distance Fields (ESDF) into GPU hardware textures before the rollout. The MPPI kernel then samples these textures in $O(1)$ time, leveraging hardware-accelerated bilinear and trilinear interpolation.

## Architecture

The environment is split into two independent texture representations:

1. **Static Environment (`Texture2D`)**:

   - Represents static line segments (road borders, drivable areas, static obstacles).
   - Maps World `(X, Y)` to continuous distance.
   - Updated only when the static map or ego-centric window shifts.
   - Interpolation: Bilinear (`cudaFilterModeLinear`).

2. **Dynamic Environment (`Texture3D`)**:
   - Represents moving objects (e.g., dynamic bounding boxes).
   - Maps World `(X, Y)` and Future Time `(T)` to continuous distance.
   - The Z-axis of the texture represents the MPPI time horizon (e.g., 80 timesteps).
   - Updated every frame based on obstacle trajectory predictions.
   - Interpolation: Trilinear (`cudaFilterModeLinear`), providing smooth gradients across both space and time.

## Implementation Pipeline

### 1. Grid Configuration

We define a localized, ego-centric grid to bound memory usage while covering the necessary MPPI spatial horizon.

```cpp
struct TextureGridConfig {
  float origin_x;     // World X of the bottom-left corner of the grid
  float origin_y;     // World Y of the bottom-left corner of the grid
  float resolution;   // Meters per pixel (e.g., 0.15f)
  int width;          // Grid width in pixels
  int height;         // Grid height in pixels
  int time_steps;     // MPPI time horizon (e.g., 80)
};

// Device helper: Grid index to World coordinate
__device__ inline void gridToWorld(
  int gx, int gy, const TextureGridConfig& cfg, float& wx, float& wy)
{
  wx = cfg.origin_x + (gx + 0.5f) * cfg.resolution;
  wy = cfg.origin_y + (gy + 0.5f) * cfg.resolution;
}

```

### 2. ESDF Generation (Compute Kernels)

Instead of rasterization, we launch one thread per grid voxel. Each thread computes the exact analytical distance to the environmental primitives. Because primitive counts are typically low (<100), this brute-force parallel approach executes in < 1ms.

```cpp
// Kernel for Static Road Borders (2D)
__global__ void generateStaticESDFKernel(
  float* out_grid, TextureGridConfig cfg,
  const float* seg_x0, const float* seg_y0,
  const float* seg_x1, const float* seg_y1, int num_segments)
{
  int gx = blockIdx.x * blockDim.x + threadIdx.x;
  int gy = blockIdx.y * blockDim.y + threadIdx.y;
  if (gx >= cfg.width || gy >= cfg.height) return;

  float wx, wy;
  gridToWorld(gx, gy, cfg, wx, wy);
  float min_dist = 1.0e8f;

  for (int i = 0; i < num_segments; ++i) {
    float dist = mppi::cost::detail::distancePointToSegment(
      wx, wy, seg_x0[i], seg_y0[i], seg_x1[i], seg_y1[i]);
    min_dist = fminf(min_dist, dist);
  }
  out_grid[gy * cfg.width + gx] = min_dist;
}

```

_(A similar 3D kernel handles oriented bounding boxes over time for the `Texture3D`.)_

### 3. Hardware Texture Binding

The linear buffers generated by the compute kernels are copied into opaque `cudaArray` memory and bound to `cudaTextureObject_t` with linear filtering enabled.

```cpp
// 1. Allocate cudaArray / cudaMalloc3DArray
// 2. Copy linear memory to array using cudaMemcpy2DToArray / cudaMemcpy3D
// 3. Configure Resource and Texture Descriptors:

cudaTextureDesc texDesc = {};
texDesc.addressMode[0] = cudaAddressModeClamp;
texDesc.addressMode[1] = cudaAddressModeClamp;
texDesc.addressMode[2] = cudaAddressModeClamp; // For 3D Time dimension
texDesc.filterMode = cudaFilterModeLinear;     // Enables Hardware Interpolation
texDesc.readMode = cudaReadModeElementType;
texDesc.normalizedCoords = 0;                  // Queries use pixel coordinates

```

## Performance Characteristics

| Metric                | Previous Approach (Analytical Math) | New Approach (Hardware Textures)                             |
| --------------------- | ----------------------------------- | ------------------------------------------------------------ |
| **Lookup Time**       | $O(N)$ per primitive per sample     | $O(1)$ single texture fetch                                  |
| **Warp Divergence**   | High (Branching per obstacle)       | None (Pure memory fetch)                                     |
| **Register Pressure** | High (Complex trigonometry)         | Low (Delegated to Texture Sampler)                           |
| **Memory Bandwidth**  | Low                                 | Medium (Texture cache hits are high due to spatial locality) |

By collapsing `distanceToClosestObstacle` and `distanceToRoadBorder` into simple `tex3D` and `tex2D` queries, the MPPI solver can evaluate significantly larger sample batches and longer time horizons within strict real-time control constraints.
