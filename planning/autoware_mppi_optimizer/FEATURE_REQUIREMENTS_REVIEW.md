# MPPI optimizer feature requirements and implementation status

Updated after the implementation commits through `48a3a7223f`. The **Your feedback** column is retained verbatim as the requirements record: **OK** accepts behavior, **NOT OK** identifies a mismatch, **Decision** states direction, and **TBD** remains unresolved. README, configuration, and implementation are evidence, not higher-authority requirements. The current-contract and status columns distinguish completed changes from the original feedback; a historical NOT OK does not imply that its corrected mismatch remains open.

The subsequent local fixes retain predicted-path admission through selector envelope pruning (SCN-01), route zero-extent references through the steering hold (NOM-08), and confirm GPU vegetation contact against the inflated footprint (SCN-15). The **Your feedback** entries remain unchanged.

Two later instructions refine that feedback: keep **only the primary candidate for now** (superseding INT-02's original request), and use **all paths tied for highest confidence** for each selected predicted object (refining SCN-08). No unresolved weighting or output policy was silently decided during implementation.

## Completed corrections and retained boundaries

- Primary-candidate handling now returns before touching parameter or execution state. Multiple-candidate optimization is deferred by the later instruction, not an outstanding mismatch for this implementation (INT-02).
- Supplied predictions, all highest-confidence ties, post-step alignment, malformed-input rejection, and explicit capacity failure are implemented (SCN-01, SCN-04–08). Capacity is still 64 hypotheses; message-age compensation remains unresolved.
- First-command exploration, zero-soft-weight hard safety checks, non-overriding collision activation, command steering default, engage in both acceleration modes, and optional interpolated validation are implemented (SMP-05, OBJ-09, GATE-08, OUT-04–05, VAL-04).
- Temporal MPT and steering EMA are removed (NOM-02, OUT-08). Generic postprocessing and transactional application history remain; old EMA-specific acceptance does not reinstate removed code (OUT-09–10).
- Timing warnings and support for encoded safety-status values in cost-test reports were added. Regression coverage was expanded, explicit ROS-message defaults fixed, CPU/GPU test registration separated where applicable, and an unrelated TensorRT build gate removed. The implementation does not claim that tests establish continuous collision safety or production latency.

## Decisions still capable of changing the next work

1. **Prediction age and capacity:** SCN-07 needs a planning epoch, freshness budget, and stale-input policy; SCN-04 still needs a capacity/scaling decision if 64 hypotheses is insufficient. All tied paths must remain represented under any replacement design.
2. **Sampling and weighting:** SMP-04, SMP-06, OBJ-10, WGT-01–06 remain open where feedback says TBD. Unsafe-rollout eligibility and final-output rejection are separate policies; percentile normalization and cycle-level ESS adaptation are retained as the current variant.
3. **Published output:** OUT-06 and VAL-11 need explicit decisions about engage consistency and the purpose of permitting validation-failing output. Sampled collision checks (SCN-17) and failure to repair an unsafe upstream input (VAL-08) are already accepted.
4. **Diagnostics:** DBG-03 needs measured selected-output breakdown cost before making it unconditional. The [GPU performance review](GPU_PERFORMANCE_REVIEW.md) identifies the CPU/GPU boundaries and a measurement plan.

Product-specific defaults are owned by products (PAR-06). They are not a blocker for the completed corrections or for profiling the present implementation.
